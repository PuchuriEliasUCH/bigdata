# Run OpenAlex and Scopus ingestion

Set `SCOPUS_API` (the existing key in `.env`) and `SCOPUS_QUERY` in the container environment to enable Scopus Search alongside OpenAlex. Keep credentials in the environment, never in a query, report, or notebook. The scheduled pipeline processes only completed Bronze batches; interrupted batches retain their checkpoint for the next run.

Scopus writes to `data/bronze/scopus/<batch_id>/`; OpenAlex writes to `data/bronze/openalex/<batch_id>/`. The state in `data/bronze/batch_metadata/` distinguishes `completed_target`, `completed_exhausted`, `quota_exceeded`, `rate_limited`, `transient_error`, `result_window_reached`, and `failed`. Scopus runs nonoverlapping `PUBYEAR = year` partitions over `INGEST_FIRST_YEAR`..`INGEST_LAST_YEAR` (default 2011 to the current year); confirmed partitions are skipped on resume. Scopus caps `start` pagination at 5,000 results per query and the `cursor` parameter is restricted for this key, so a partition whose first page reports more than 5,000 results is marked `oversized`, its page is not stored, and it is split into two disjoint `ORIG-LOAD-DATE` windows (`AFT`/`BEF` are exclusive). Windows keep open ends, so together they cover the whole history of the query, and split points are fixed so reruns never refetch. Scopus answers an empty result set with one error entry, so a zero total means no records and error entries are never stored; an empty window leaves no page and no Silver batch. A single day that still exceeds the window is fetched up to the cap and marked `result_window_reached`; it is terminal and does not block other partitions. Once every year's initial quota is reached, each run spends an incremental budget (`INCREMENTAL_LIMIT`, 1,000 records by default) on the least filled year first until results end or the quota is exhausted.

Silver keeps one row per source record, with `source`, `source_id`, `batch_id`, and `normalized_doi`. Use `unique_publications(records)` for an analysis view: it prefers OpenAlex for a shared DOI while leaving records without DOI individually traceable. Bronze retains the original responses for auditing. The output partition target is 100,000 input rows per file, with Snappy compression; measure actual counts before tuning it (see [measurement](ingestion-measurement.md)).

For historical small files, call `compact_batches(spark, silver_root, batch_ids, group="openalex-2024")` for batches of one source with identical schemas. Only group batches after confirming their year range is appropriate for the analytical query. The task validates row count and schema before atomically publishing a manifest. Consumers must use `active_silver_paths(silver_root)` to read one version of each group; wildcard-reading `works/` bypasses the manifest. Original data remains available for rollback until the optional explicit `prune_compacted_originals(spark, silver_root, group)` revalidates the published generation and removes the original batch directories. Reprocessing from Bronze remains possible after pruning.

## Search criteria

Both sources derive their search from one term list, `AI_TERMS` in `src/search_criteria.py`, so they describe the same population: Scopus uses `TITLE-ABS-KEY(...)` and OpenAlex uses `title_and_abstract.search:(...)`. Run `python -m src.search_criteria` to print both expressions. `SCOPUS_QUERY` is still taken from the environment and is never invented; `OPENALEX_FILTER` overrides the shared definition, and `none` disables it. OpenAlex batch state is scoped to the filter, so changing it starts a fresh initial ingestion; data ingested without a filter stays in Bronze and Silver until it is purged. Document type and language are not filtered at ingestion; they belong to the Silver filtering step.

## Parquet layers

Bronze pages are Parquet (`page-NNNNNN.parquet`: `batch_id`, `page_number`, `record_index`, `record_json`), rejected rows are Parquet, and Silver is Parquet. Only control files (`batch_metadata/*.json`, `_processing/*.json`, compaction manifests) stay JSON. Spark still reads JSON pages written before this change, including a batch that mixes both formats.

## Year-stratified ingestion

Both sources ingest the same year range with an initial target (`INGEST_INITIAL_TARGET`, 100,000 per source) split across years in proportion to each year's real volume, so recent years are not starved by early ones. Year volumes come from one OpenAlex `group_by` request and one single-record Scopus request per year; the resulting plan is stored in `bronze/plans/<source>.json` and reused while the query or filter, range and target are unchanged. OpenAlex runs one filter lineage per year (`publication_year:Y`), so cursors never mix. Within a year, the order of records follows each API's own order, which is not random. Document type and topical filtering belong to Silver, which is why ingestion takes everything the AI expression matches.

## Automatic compaction

After each Silver run, `compact_pending` groups uncompacted batches by source and publication year (taken from the ingestion lineage: the OpenAlex filter or the Scopus base query). Once a group has `COMPACT_MIN_BATCHES` batches (default 10) it publishes a new immutable group such as `openalex-2024-0001`, validates row counts and schema, writes it through the manifest, and removes the originals. Later rounds publish `-0002`, so nothing already compacted is rewritten and no old generation is left behind. Rejected rows of the same batches are compacted with the group. A group whose schemas do not match is skipped and reported as `compaction_skipped`; the run continues. Readers must use `active_silver_paths` and `active_rejected_paths`, never a wildcard over `works/` or `rejected/`.

## Time budget per run

Each run gets `INGEST_TIME_BUDGET_SECONDS` (default 30, shared evenly by the active sources) so the one-minute scheduler never overlaps itself and Spark plus compaction still fit in the cycle. Before every API request an ingester compares the clock with its deadline; when it has passed, the batch is saved as `time_budget_reached` with its cursor or offset and the run ends. The next run resumes that batch, and because a paused batch is not complete it never reaches Silver half-filled, so a time cut does not fragment data. This applies to the initial load too, which is spread over several runs. `INCREMENTAL_LIMIT` (3,000) is only a cap on records per run. Planning requests (year totals) are not counted in the budget and run once.

OpenAlex reads its credits once per batch instead of before every page, which halves the requests of a long batch. A one-off continuous initial load is described in `documentacion/operacion.md`.
