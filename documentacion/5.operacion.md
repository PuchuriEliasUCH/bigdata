# Operación y configuración

Cómo configurar, ejecutar y verificar cada fase. Todos los comandos se lanzan desde la raíz del
repositorio. El contenedor corre como `root` y `data/` pertenece a `root` en el host: lea los datos con
el contenedor o con permisos de lectura, y escriba en `data/` solo a través del contenedor.

## Comandos rápidos

| Tarea | Comando |
|---|---|
| Arrancar el servicio programado (cron + Jupyter) | `docker compose -f compose.yaml up -d --build` |
| Detener el servicio | `docker compose -f compose.yaml stop spark-pipeline` |
| Una ejecución manual del pipeline | `docker compose -f compose.yaml run --rm spark-pipeline python -m src.run_pipeline` |
| Reconstruir Silver sin ingesta | [Ver abajo](#reconstruir-silver-sin-ingesta) |
| Construir Gold | [Ver abajo](#construir-gold) |
| Congelar lotes pausados | [Ver abajo](#congelar-lotes-pausados) |
| Pruebas | `docker compose -f compose.yaml run --rm --build --no-deps spark-pipeline pytest -q` |

La imagen que construye Compose se llama `bigd_g2-spark-pipeline:latest`. `src/` y `tests/` se copian en
la imagen ([Dockerfile](../Dockerfile)): después de cambiar código hay que reconstruirla (`--build`).

## Configuración

Compose carga `.env` ([compose.yaml](../compose.yaml)), fija `BRONZE_PATH=/data/bronze`,
`SILVER_PATH=/data/silver`, `GOLD_PATH=/data/gold` y `TZ=UTC`, monta `./data` en `/data` y
`./notebooks` en `/app/notebooks` (solo lectura), y expone Jupyter en el puerto 8888.

| Variable | Valor por defecto | Uso |
|---|---|---|
| `OPENALEX_TOKEN` | — (obligatoria) | Credencial de OpenAlex. Sin ella la ejecución falla. |
| `OPENALEX_FILTER` | Filtro de IA de [`search_criteria.py`](../src/search_criteria.py) | Sustituye el filtro; `none` lo desactiva. Cambiarlo inicia lotes y plan nuevos. |
| `SCOPUS_API` | — | Credencial de Scopus. |
| `SCOPUS_QUERY` | Vacía | Habilita Scopus. El código no la genera. |
| `INGEST_FIRST_YEAR`, `INGEST_LAST_YEAR` | 2011 y el año actual UTC | Rango de ambas fuentes. |
| `INGEST_INITIAL_TARGET` | 100 000 | Registros iniciales por fuente, repartidos por año. |
| `INCREMENTAL_LIMIT` | 6 000 (1 000 en los módulos) | Tope por fuente y ejecución incremental. |
| `INGEST_TIME_BUDGET_SECONDS` | 70 | Tiempo de ingesta por ejecución. |
| `INGEST_SCOPUS_SHARE` | 0,6 | Parte de ese tiempo para Scopus si está activo. |
| `SCOPUS_REQUESTS_PER_SECOND` | 5 (2 en el módulo) | Ritmo de solicitudes a Scopus. |
| `SILVER_TIME_BUDGET_SECONDS` | 20 | Plazo para iniciar lotes Silver; siempre procesa al menos uno. |
| `COMPACT_MIN_BATCHES` | 10 | Lotes sueltos por fuente y año que activan la compactación. |
| `SPARK_MASTER` | `local[*]` | Master de Spark. |
| `BRONZE_PATH`, `SILVER_PATH`, `GOLD_PATH` | `/data/bronze`, `/data/silver`, `/data/gold` | Rutas de las capas. |

No imprima ni publique los valores de las credenciales.

## Ejecución programada

[`entrypoint.sh`](../docker/entrypoint.sh) inicia JupyterLab en segundo plano y deja a Supercronic como
proceso principal con [`pipeline.cron`](../scheduler/pipeline.cron): `python -m src.run_pipeline` cada
dos minutos. El recorrido de cada ejecución está en
[Ingesta: qué pasa en una ejecución](1.ingesta.md#qué-pasa-en-una-ejecución).

Cada ejecución termina con una línea JSON en los logs (`docker compose -f compose.yaml logs -f
spark-pipeline`):

| Campo | Significado |
|---|---|
| `event` | `pipeline_complete` o `pipeline_partial`. |
| `openalex_status`, `scopus_status` | Primer estado que aún requiere atención en cada fuente, o el último. |
| `ingested_records`, `ingested_pages`, `batch_id`, `batch_mode` | Totales y último lote OpenAlex. |
| `ingestion_seconds`, `silver_seconds` | Duración real (Silver incluye compactación y cierre de Spark). |
| `processed_batches`, `skipped_batches`, `silver_pending_batches` | Lotes Silver procesados, ya hechos y pendientes por plazo. |
| `silver_schema_version`, `silver_rebuilt` | Versión vigente y si esta ejecución reconstruyó Silver. |
| `compacted_groups`, `compaction_skipped` | Grupos publicados y grupos que fallaron. |
| `valid_rows`, `rejected_rows` | Filas Silver escritas en esta ejecución. |

Algunos errores impiden esa línea: falta de `OPENALEX_TOKEN`, un error de red en el conteo anual de
Scopus o una página Bronze ilegible al procesar Silver. Revise los logs en lugar de suponer éxito.

### Carga inicial con presupuesto ampliado

Con 70 s por ejecución, la carga inicial se reparte en muchas ejecuciones. Para acelerarla, detenga el
servicio, lance una ejecución larga y vuelva a arrancarlo:

```bash
docker compose -f compose.yaml stop spark-pipeline
docker compose -f compose.yaml run --rm -e INGEST_TIME_BUDGET_SECONDS=86400 spark-pipeline python -m src.run_pipeline
docker compose -f compose.yaml up -d
```

Cada fuente puede terminar antes. Si se interrumpe, la siguiente ejecución retoma desde el cursor u
offset guardado.

## Reconstruir Silver sin ingesta

Útil tras cambiar `SILVER_SCHEMA_VERSION` o para procesar todo de una vez con la ingesta congelada. Se
llama directamente a [`process_pending_batches`](../src/spark_pipeline.py) sin plazo y luego a
[`compact_pending`](../src/compaction.py), sin tocar las API:

```bash
docker compose -f compose.yaml stop spark-pipeline
docker run --rm -v "$PWD/data:/data" -w /app -e PYTHONPATH=/app \
  --entrypoint python bigd_g2-spark-pipeline:latest -c '
from pathlib import Path
from pyspark.sql import SparkSession
from src.spark_pipeline import process_pending_batches
from src.compaction import compact_pending
spark = SparkSession.builder.master("local[*]").config("spark.ui.enabled", "false").getOrCreate()
bronze, silver = Path("/data/bronze"), Path("/data/silver")
print(process_pending_batches(spark, bronze, silver))
print(compact_pending(spark, bronze, silver))
spark.stop()'
```

Si la versión de esquema cambió, la primera llamada borra Silver derivado y lo reconstruye desde
Bronze ([detalle](3.silver.md#0-versión-de-esquema)). Antes de hacerlo, confirme que las páginas Bronze
existen: el control previo solo exige los metadatos. La última reconstrucción completa (2026-10-10)
procesó 303 lotes y publicó 14 grupos; la ejecución final duró 2 489 s.

## Construir Gold

Requiere Silver completo (0 lotes pendientes, versión 4) y `data/` montado con escritura:

```bash
docker compose -f compose.yaml build
docker run --rm -v "$PWD/data:/data" -w /app -e PYTHONPATH=/app \
  --entrypoint python bigd_g2-spark-pipeline:latest -m src.gold_pipeline
```

Termina con una línea JSON `gold_complete` con `universe_rows`, `topic_count`, `rows`, `labeled_rows` y
`positive_rows`. Valores esperados en el corte actual: 300 171, 3 492, 52 380, 3 308 y 289. Si no
coinciden, no avance al modelado. Volver a ejecutar reemplaza Gold de forma atómica
([publicación](4.gold.md#58-validación-y-publicación)).

## Congelar lotes pausados

Silver solo lee lotes terminales. Cuando la ingesta se detiene para siempre, los lotes pausados con
páginas quedarían fuera. [`freeze_batches`](../src/freeze_batches.py) los marca como `frozen`
([detalle](1.ingesta.md#congelamiento)):

```bash
docker compose -f compose.yaml stop spark-pipeline
docker compose -f compose.yaml run --rm --no-deps spark-pipeline python -m src.freeze_batches
```

Imprime un JSON con `frozen_batches` y sus identificadores; la siguiente ejecución de Silver los
procesa. Es permanente: ninguna ingesta retoma un lote congelado. Una ingesta futura crea lotes nuevos
y la deduplicación de Silver descarta los registros repetidos.

## Notebooks de evidencia

| Notebook | Lee | Muestra |
|---|---|---|
| [`openalex_pipeline_evidence.ipynb`](../notebooks/openalex_pipeline_evidence.ipynb) | `data/bronze`, `data/silver` | Lotes, páginas, ventanas Scopus, estado Silver, totales, cobertura, indicadores, rechazos, fracción muestreada, solapamiento por DOI. |
| [`gold_evidence.ipynb`](../notebooks/gold_evidence.ipynb) | `data/gold` | Manifiesto, clases, sensibilidad, particiones, variables por clase, tópicos emergentes. |

Ambos son de solo lectura. Para regenerarlos con salidas, ejecútelos dentro de la imagen (como `root`,
el usuario por defecto) con `data/` en solo lectura y escriba el resultado fuera del repositorio
(`OUT` es un directorio temporal):

```bash
NB=gold_evidence.ipynb   # o openalex_pipeline_evidence.ipynb
docker run --rm -v "$PWD/data:/data:ro" -v "$PWD/notebooks:/work:ro,Z" -v "$OUT:/out:Z" \
  -w /app -e PYTHONPATH=/app --entrypoint jupyter bigd_g2-spark-pipeline:latest \
  nbconvert --to notebook --execute --output-dir /out --output "$NB" \
  "/work/$NB" --ExecutePreprocessor.timeout=1800
```

Revise el resultado en `$OUT` y cópielo a `notebooks/` si corresponde. Para explorar en vivo, el
servicio programado expone JupyterLab en `http://localhost:8888` (sin token: solo para uso local).

## Comprobaciones útiles

1. **Configuración.** `docker compose -f compose.yaml config --quiet` valida Compose sin imprimir
   valores. Confirme si `SCOPUS_QUERY` está definida y el rango de años efectivo.
2. **Bronze.** Sección 4 del notebook de calidad: "lotes con páginas que no son terminales" debe ser 0
   antes de construir Gold.
3. **Silver.** Sección 5: todos los lotes terminales con páginas `completed`. Sección 6: versión 4 en
   disco y en código, 0 pares (`source`, `source_id`) repetidos.
4. **Lectura.** Leer Silver siempre con `active_silver_paths` y `active_rejected_paths`, nunca solo
   `works/*`.
5. **Gold.** `data/gold/_manifest.json`: `silver_schema_version = 4`, conteos esperados y la regla.
6. **Ejecuciones programadas.** En la línea JSON, `silver_pending_batches = 0` y `compaction_skipped`
   vacío.
