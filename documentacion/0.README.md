# Proceso general: de las API a la tabla tópico × año

El pipeline construye un corpus de publicaciones de inteligencia artificial (OpenAlex y Scopus), lo
depura y lo convierte en una tabla tópico × año con una etiqueta de "tópico emergente". Esta
documentación explica cada fase, cómo se pasa a la siguiente y qué resultados se pueden obtener en
cada una. Describe el código actual; las cifras corresponden al corte del corpus (ver
[instantánea](#instantánea-de-cifras-2026-10-10)).

## Objetivo de investigación

> A partir de la información histórica disponible sobre un tópico de investigación en IA hasta un año
> base `t`, predecir si ese tópico se convertirá en emergente en un horizonte futuro.

La unidad de análisis es un tópico observado en un año. Las variables usan solo información hasta `t`;
la etiqueta se construye con lo que ocurrió después ([context.md](../context.md)).

## Recorrido de extremo a extremo

```text
 OpenAlex Works API          Scopus Search API
 (siempre se intenta)        (solo si SCOPUS_QUERY no está vacía)
          │                           │
          └──── ingesta por año ──────┘     src/ingestion.py, cuotas en src/quotas.py
                      │
                      v
 BRONZE   data/bronze/                      respuestas crudas, una fila por registro
          <fuente>/<lote>/page-*.parquet    + batch_metadata/<lote>.json + plans/<fuente>.json
                      │  lotes terminales con páginas
                      v
 SILVER   data/silver/                      src/spark_pipeline.py
          works/ · rejected/ · _processing/ · _compact/ (compactación)
          reglas mínimas + deduplicación + indicadores de calidad (v4)
                      │  universo: OpenAlex, elegible, consulta común, 2011–2025, con tópico
                      v
 GOLD     data/gold/                        src/gold_pipeline.py
          year_totals/ · topic_year/ · _manifest.json
                      │  partición temporal (label_end_year <= E)
                      v
 MODELOS  baselines y red neuronal          próximo hito, no implementado
                      │
                      v
 DSS      probabilidades, rankings, evolución temporal (objetivo del proyecto)
```

Bronze y Silver se alimentan solos: el contenedor ejecuta
[`run_pipeline`](../src/run_pipeline.py) cada dos minutos (ingesta, Silver y compactación). Gold se
ejecuta a mano cuando Silver está completo. La ingesta está congelada desde el 2026-10-09.

## Las capas en una tabla

| Capa | Pregunta que responde | Entrada | Salida | Cómo se pasa a la siguiente | Comando |
|---|---|---|---|---|---|
| [Ingesta](1.ingesta.md) | ¿Qué registros pedimos a cada API y cuántos por año? | API de OpenAlex y Scopus, `AI_TERMS`, plan de cuotas | Páginas y metadatos de lote en Bronze | Cada lote avanza hasta un estado terminal (completo, agotado, congelado…) | `python -m src.run_pipeline` (cron) |
| [Bronze](2.bronze.md) | ¿Qué devolvieron exactamente las API? | Respuestas de las API | `bronze/<fuente>/<lote>/page-*.parquet`, `batch_metadata/`, `plans/` | Silver toma los lotes con estado terminal para su fuente y `page_count > 0` | El mismo de la ingesta |
| [Silver](3.silver.md) | ¿Qué registros son válidos y únicos, y con qué calidad? | Lotes terminales de Bronze | `silver/works`, `silver/rejected`, `_processing`, `_compact` | Gold filtra el universo comparable con los indicadores de Silver v4 | `python -m src.run_pipeline` (o reconstrucción manual, ver [operación](5.operacion.md)) |
| [Gold](4.gold.md) | ¿Qué tópicos crecieron de forma sostenida y con qué señales previas? | Silver v4 (vía `active_silver_paths`) y `plans/openalex.json` | `gold/year_totals`, `gold/topic_year`, `gold/_manifest.json` | El entrenamiento aplica la regla temporal `label_end_year <= E` | `python -m src.gold_pipeline` |
